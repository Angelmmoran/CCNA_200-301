## STP (Spanning Tree Protocol)

STP resuelve un problema que se presenta al configurar redundancia en una red.
La redundancia es esencial para asegurar la continuidad de una red en caso de una caída de una parte de la red. 

![](Pasted%20image%2020261017101331.png)

En esta red, si un SW o un Router falla, hay mas caminos hacia internet o hacia el resto de los hosts. 
Sin embargo, sin STP, se puede generar un Broadcast Storm dentro de la red. 
Broadcast Storm ocurre cuando un paquete de broadcast se quede atrapado entre tres o mas SW de forma permanente. Esto no se arregla con TTL. Estos paquetes atrapados, harán que la red esté saturada. STP es la solución a este problema.

El porotoclo clasico es IEE 802.1D. Este protocolo es tan importante, que todos los fabricantes corren este protocolo en sus dispositivos, no solo CISCO.

![](Pasted%20image%2020261017102111.png)

En esta red, la conexión con putos representa un conexión existente pero desactivada para evitar el Broadcast Storm. Si alguna de las otras interfaces de conexión entre los SW falla, ellos mismos activan la interfaz desactivada y desactivan la que falla para que la red siga teniendo conexión.
STP elige que puertos están en forwarding y cuales en blocking. Estos estados se eligen siguiendo unos procesos.

Con STP, los SW envían cada 2 seg un "Hello STP BPDU" a través de todas sus interfaces. Si un SW recibe un "Hello STP BDPU" sabe que esa interfaz está conectada a otro SW.

### Procesos de STP
#### ¿Que es el bridge ID?
Está compuesto por Bridge Priority (16 bits) y MAC Address (48 bits). El valor por defecto de Bridge Priority es 32768.

Bridge Priority se divide en 2: Bridge Priority (4 bits) y Extended System ID (VLAN ID) (12 bits)

Los SW usan este bridge ID para elegir el **root bridge**. Todos los puertos del root bridge se configuran en forwarding state, y otros SW de la red deben tener rutas a ese SW. Si hay empate, se usa como brake la MAC Address.

### STP Path Costs

| Velocidad | STP Cost |
| :-------: | :------: |
|  10 Mbps  |   100    |
| 100 Mbps  |    19    |
|  1 Gbps   |    4     |
|  10 Gbps  |    2     |

Root cost es la suma de todos los costes de interfaces de salida hasta llegar al root bridge. 
Las interfaces del root bridge tienen un coste de 0.
SW1 (root bridge) enviará el BDPU con su coste (0). SW2 y SW3 añadirán su coste al BDPU cuando lo reenvíen.

## Resumen

1) Un SW es elegido como root bridge. Todos sus puertos se configuran como **designated ports** en forwarding state. Este root bridge será el que tenga el Bridge ID mas bajo.
2) Los SW restantes eligen UNA de sus interfaces como **root port** en FW State. El root port se elige:
	1) Root cost mas bajo
	2) Bridge ID de SW vecino mas bajo
	3) Port ID de SW vecino mas bajo
3) Los collision domains restantes eligen UNA interfaz como designated port en FW State, los demás como non-designated (blocking). Designated ports se eligen:
	1) Interfaz del SW con menor root cost
	2) Interfaz de SW con menor bridge ID
