## STP (Spanning Tree Protocol)

STP resuelve un problema que se presenta al configurar redundancia en una red.
La redundancia es esencial para asegurar la continuidad de una red en caso de una caída de una parte de la red. 

![](../999-Imágenes/Pasted%20image%2020261017101331.png)
En esta red, si un SW o un Router falla, hay mas caminos hacia internet o hacia el resto de los hosts. 
Sin embargo, sin STP, se puede generar un Broadcast Storm dentro de la red. 
Broadcast Storm ocurre cuando un paquete de broadcast se quede atrapado entre tres o mas SW de forma permanente. Esto no se arregla con TTL. Estos paquetes atrapados, harán que la red esté saturada. STP es la solución a este problema.

El porotoclo clasico es IEE 802.1D. Este protocolo es tan importante, que todos los fabricantes corren este protocolo en sus dispositivos, no solo CISCO.

![](../999-Imágenes/Pasted%20image%2020261017102111.png)

En esta red, la conexión con putos representa un conexión existente pero desactivada para evitar el Broadcast Storm. Si alguna de las otras interfaces de conexión entre los SW falla, ellos mismos activan la interfaz desactivada y desactivan la que falla para que la red siga teniendo conexión.
STP elige que puertos están en forwarding y cuales en blocking. Estos estados se eligen siguiendo unos procesos.

Con STP, los SW envían cada 2 seg un "Hello STP BPDU" a través de todas sus interfaces. Si un SW recibe un "Hello STP BPDU" sabe que esa interfaz está conectada a otro SW.

**BPDU -> Bridge Protocol Data Unit**

### Procesos de STP
#### ¿Que es el bridge ID?
Está compuesto por Bridge Priority (16 bits) y MAC Address (48 bits). El valor por defecto de Bridge Priority es 32768.

Bridge Priority se divide en 2: Bridge Priority (4 bits) y Extended System ID (VLAN ID) (12 bits)

Los SW usan este bridge ID para elegir el **root bridge**. Todos los puertos del root bridge se configuran en forwarding state, y otros SW de la red deben tener rutas a ese SW. Si hay empate, se usa como brake la MAC Address.

## STP states/timers

### States

| STP Port State | Envía/Recibe BPDUs | Tráfico normal | Aprende MACs | Stable/Transitional |
| :------------: | :----------------: | :------------: | :----------: | :-----------------: |
|    Blocking    |      NO / SI       |       NO       |      NO      |       Stable        |
|   Listening    |      SI / SI       |       NO       |      NO      |    Transitional     |
|    Learning    |      SI / SI       |       NO       |      SI      |    Transitional     |
|   Forwarding   |      SI / SI       |       SI       |      SI      |       Stable        |
|    Disabled    |      NO / NO       |       NO       |      NO      |       Stable        |

Non-designated ports están en estado **Blocking**. Estas interfaces están, a efectos prácticos, desactivadas. Estas interfaces no envian ni reciben trafico regular; pero si reciben STP BPDU. NO ENVÍAN STP BPDU NI TAMPOCO aprenden direcciones MAC.

**Listening state** es un estado de transición para las Designated o Root. Este estado dura 15 segundos por defecto, está determinado por el **Foward timer**. Una interfaz en Listening State SOLO envía y recibe STP BPDU, el tráfico normal es dropeado. No aprende MACs.

**Learning state** también dura 15 segundos (mismo timer que Listening). Igual que el anterior, solo envía o recibe STP BPDU y el tráfico normal lo dropea. La diferencia es que en este estado SI aprende MACs.

**Forwarding State** opera de forma normal.

### Timers

|   STP Timer   |                                                   Uso                                                   |        Duración         |
| :-----------: | :-----------------------------------------------------------------------------------------------------: | :---------------------: |
|     Hello     |                         Frecuencia con la que el root bridge envía "hello BPDU"                         |       2 segundos        |
| Forward Delay |                      El tiempo que un SW va a estar en Listening o Learning state                       |       15 segundos       |
|    Max Age    | Cuanto tiempo va a esperar una interfaz después de dejar de recibir "Hello BPDU" para cambiar su estado | 20 segundos (10* hello) |
#### ¿Cómo funciona Max Age?

Cada vez que una interfaz recibe un "Hello BPDU", el contador vuelve a 20seg. Va bajando hasta que:
	- Recibe otro "Hello BPDU" y reinicia el contador a 20.
	- Su contador llega a 0 porque no recibe ningún "Hello BPDU" por un fallo en la conexión.
En el segundo caso, el SW reevaluará su STP (root bridge, local root, desginated y non-desiganted ports)
Si un non-designated port ese elegido para convertirse en **designated o root port**, pasará a **Listening State**, luego a **Learning State** y finalmente a **Forwarding State**. Por defecto, la transición entre blocking state y forwarding state puede durar un total de 50 segundos. Tarda tanto tiempo para para asegurarse que no se crean loops por cambiar de estado demasiado pronto.

## STP configuration 

STP funciona por defecto, no hay que configurar nada. Aquí se tratan la configuración en general para conocer como funciona, y alguna configuración opcional.

-**Portfast**: es una configuración opcional que permite a un SW saltarse los estados de Listening y Learning cuando pasa de Blocking a Forwarding. Esta configuración SOLO debe usarse (si se usa) en interfaces conectadas a Endhosts. Usarla en interfaces conectadas a otros SW puede provocar loops.

-**BPDU Guard**: si una interfaz con BPDU Guard recibe un BPDU de otro SW, esta interfaz se desactiva automáticamente para prevenir loops. Se activa con: *spanning-tree bpduguard enable*

-**Root Guard**: si se activa, si el SW recibe un BDPU superior (con menor bridge ID) en esa interfaz, el SW no aceptará el nuevo SW como root y desactivará la interfaz. 

-**Loop Guard**: si está activa, aunque la interfaz deje de recibir BDPUs, no pasará a FW state, será desactivada.

El comando *spanning-tree mode ?* nos mostará tres comandos:
	mst                 Multiple spanning tree mode
	pvst                 Per-Vlan spanning tree mode
	rapid-pvst       Per-Vlan rapid spanning tree mode

El comando *spanning-tree vlan (num vlan) root primary* configura la prioridad de la interfaz a 24576, si ya existe in SW con esta prioridad, la baja a razon de 4096 hasta que es el SW con menor prioridad.

El comando *spanning-tree vlan (num vlan) root secondary* configura la prioridad de la interfaz para ser la segunda interfaz con menor prioridad.
