## ¿Qué es BPDU Guard?

Es una característica que evita problemas si hay cambios en la topología STP de una red (por ejemplo si se conecta un SW sin configurar correctamente).
#### ¿Cómo funciona?

En este caso, Bob ha conectado un SW sin autorización, y este ha empezado a enviar BPDUs a la red. Sin BPDU Guard, esto podría alterar la estructura STP. 

El puerto de SW3 está configurado como BPDU Guard, sigue enviando BPDUs pero si los recibe se pondrá en estado *error-disabled*  para evitar loops (lo mismo que disabled).

Se puede configurar con *spanning-tree bpduguard enable* en las interfaces que queramos; o puede configurarse por defecto en todo el SW con el comando *spanning-tree portfast bpduguard default*. Si queremos desactivarlo en alguna interfaz, usamos *spanning-tree bpduguard disable*.

Hay dos formas de volver a activar una interfaz que ha sido err-disabled:
- Manual, usando *shutdown* y *no shutdown*.
- Automático, con *ErrDisable Recovery*:
	- Para ver información, usamos *show errdisbale recovery* y veremos una lista de los motivos por los que se ha podido poner este este modo, y si la recuperación automática está activada o no. Viene desactivada por defecto. 
	 Para activarlo, usamos *errdisable recovery cause* (causa) para activarlo para esa causa.
## ¿Qué es BPDU Filter?

Un puerto de un SW conectado a un endhost enviará BPDUs cada dos segundos, estén o no activados PortFast o BPDU Guard. 
Si el puerto no está conectado a otro SW, enviar BPDUs es innecesario e indeseado:
- No es necesario porque es inútil, el endhost lo va a ignorar, y estamos usando recursos del SW para nada (aunque el gasto es mínimo, pero existe).
- El paquete BDPU contiene información sobre la configuración STP de la red. Para mayor seguridad, esta información no debería enviarse a los endhost. 

BPDU Filter desactiva el envío de BPDUs en un puerto. Se puede activar en una interfaz o como default en el SW:
- Para solo un puerto, en la interfaz: *spanning-tree bpdufilter enable*. El puerto no enviará e ignorará los paquetes BPDU. Básicamente, desactiva STP en el puerto (==🔴**usar con cuidado**==).
- Para activarlo en todo el SW, usamos *spanning-tree portfast bpdufilter default* (**esta es una mejor práctica**). El puerto no envía paquetes BPDUs, pero si lo recibe, Portfast y BPDU Filter están activados, asique actúa como un puerto normal STP.

## Recomendaciones para buenas prácticas y notas

- Activar PortFast y BPDU Guard como creamos mas conveniente, y ==🔴SOLO ACTIVAR BPDU== Filter como default desde global config mode (nunca por puerto, a no ser que tengamos una muy buena razón para hacerlo).

- BPDU Guard y Filter pueden activarse a la vez en el mismo puerto, pero su comportamiento dependerá de como esté configurado:
	- Si BPDU Filter se activó en **global config mode** y el puerto recibe BPDU:
		- 1. BPDU Filter se desactiva.
		- 2. BPDU Guard actuará y la interfaz estará en err-disable.
	- Si BPDU Filter se activó en **interface config mode** y el puerto recibe BPDU:
		- 1. El paquete BPDU será ignorado.
		- 2. BPDU Guard no actuará.
